## Why

`expand-job-seeker-coverage` packaged overlay core/B-tier growth, but verified global coverage still stops short of an end-to-end loop. The ten built-in ATS families overclaim or under-prove listing and exact-get, overlay work-order copy still carries US-weighted sequencing, new ATS families can look adoptable from one-off HTML, public job JSON is still an unrestricted model dump, and catalog-row counts can pass for quality. Mixing those gaps into catalog `SyncMetrics`, pull `PullTerminalObservability`, scout JSON, or web telemetry would invent a shared `RunMetrics` envelope and steal writers from sibling campaigns.

This successor keeps overlay core/B-tier names, the per-employer outcome enum, quarantined discovery, and URL-match locators. It deepens the ten ATS families, continues overlay and household-index boards with global knowledge-work acquisition order, admits new public ATS families only behind a demand-and-proof gate, ships a governed hybrid job-record contract (versioned `core`/`search`/`full`/`raw` plus companion observations), and stops on executable quality floors rather than padded source counts. It does not publish live, does not land Alembic `0005` or `0006`, and does not mix the four observability stacks.

## What Changes

- Freeze honest capability manifests for the ten built-in ATS ids (`greenhouse`, `lever`, `ashbyhq`, `workable`, `workday`, `rippling`, `teamtailor`, `bamboohr`, `consider_jobs`, `wpjobmanager`): listing completeness, pagination/terminal evidence, and native versus board-scan exact-get. Ashby, Workable, and Teamtailor remain board-scan get only. Consider has no get at G0; exact-get arrives in G2 from evidence, not a fake native hook.
- Deny-list Indeed and Glassdoor beside LinkedIn and Wellfound. Keep Wellfound, AngelList, WorkAtAStartup, and LinkedIn out. No CB-unicorn rank feed.
- Continue packaged overlay core/expand/growth and household indexes (`fortune500`, `sp500`, `nasdaq100`, `sec-company-tickers`, `yc`) with one conserved outcome per employer. Locators stay URL-match only. Packaged gain excludes url-pull and scout. Acquisition order is global knowledge-work, not US-weighted.
- Admit a new public ATS family only when it is unauthenticated, unlocks sought-after employers, and proves listing plus exact-get with a capability manifest, deterministic fixtures, and a field-promotion-separate namespaced extension. One-off HTML does not register a provider.
- Ship versioned public JSON profiles `core`, `search`, `full`, and `raw`. Each emitted object identifies `profile` and `schemaVersion`. Default CLI export profile is `full`; web artifacts use `search`.
- Add companion observations with origin `provider_observed` | `openopps_derived` | `editorial`, compact origin tags on projections, and compute-at-projection until a later storage campaign. No Alembic `0005` or `0006` from this change. Do not rewrite `storage.py` `_unique_jobs_by_id`.
- Add an isolated quality-floor reporter (T2 indexability, listing/detail conflict, null/parse, capability gaps, diminishing-yield stop). That report is not `SyncMetrics` and not `PullTerminalObservability`.
- Keep four isolated observability stacks: catalog `SyncMetrics` on `--metrics-json`, pull `--metrics-file` / `PullTerminalObservability`, discovery JSON, and web telemetry. Thin `--profile` on `jobs export` / `jobs pull` after profile modules exist. Optional admin/providers quality diagnostic is not `--metrics-json`.
- Discovery scout, verify-scout, `launch_isolated_scout`, and preview-promotion never share a run with `openopps sync`. No Workers upload, Kaggle mutation, source-policy 1780 grants, or hosted publish from this change.

## Capabilities

### New Capabilities

None. Honest ATS manifests, overlay successor rules, demand-gated admission, versioned profiles, companion observations, and isolated quality floors extend existing provider-ingestion, provider-coverage, storage-export, CLI, and docs-product-boundary capabilities.

### Modified Capabilities

- `provider-ingestion`: Honest ten-ATS capability manifests; listing and exact-get evidence; Consider exact-get after proof; Ashby/Workable/Teamtailor board-scan get only; Indeed/Glassdoor unsupported like LinkedIn/Wellfound; overlay locators URL-match only; new-family admission gate; discovery never shares a run with `openopps sync`.
- `provider-coverage`: One conserved overlay outcome per employer; packaged gain excludes url-pull and scout; global (not US-weighted) acquisition order; isolated quality-floor reporter and diminishing-yield stop; quality report is not `SyncMetrics` and not `PullTerminalObservability`.
- `storage-export`: Public JSON identifies `profile` + `schemaVersion`; `core`/`search`/`full`/`raw` field intent; observed vs derived distinguishable; companion observations compute-at-projection; no new Alembic from this change; default CLI profile `full`; web artifacts `search`.
- `cli-domain`: Thin `--profile` on `jobs export` / `jobs pull` after modules exist; optional admin/providers quality diagnostic that is not `--metrics-json`; four observability stacks stay isolated; CLI-first with no hosted publish from this change.
- `docs-product-boundary`: Document CLI-first successor coverage, versioned profiles, honest ATS capabilities, and the no-live-publish / no-source-policy-1780 boundary. Nested AGENTS and public docs update only if public CLI/help actually changes.
