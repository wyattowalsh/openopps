# docs-product-boundary Specification

## ADDED Requirements

### Requirement: Successor coverage remains CLI-first without hosted publication

Public product documentation SHALL describe this coverage campaign as CLI-first local work: deepen built-in ATS families, continue overlay and household indexes, admit new families only behind a demand-and-proof gate, emit versioned job profiles, and stop on quality floors. Documentation SHALL NOT treat this change as authorization to upload Cloudflare Workers, bootstrap production, mutate Kaggle, fabricate source-policy 1780 grants, land Alembic `0005` or `0006`, or publish hosted job data. Nested `AGENTS.md` and public docs SHALL update only if public CLI or help actually changes.

#### Scenario: A user reads product scope documentation

- **WHEN** a user reads README, Docs, or nested AGENTS about coverage expansion
- **THEN** OpenOpps describes CLI commands as the primary power path
- **AND** it does not advertise in-browser sync, live database hosting, Workers upload, or Kaggle mutation as work from this change

#### Scenario: Docs update only after public CLI help changes

- **WHEN** implementation adds no public CLI or help change
- **THEN** this change does not require a public docs rewrite
- **AND** ignored `goals/*` files are not treated as tracked OpenSpec completion evidence

### Requirement: Public docs describe versioned profiles and honest ATS capabilities

When public CLI/help or docs pages describe job output or providers after this campaign, they SHALL name versioned profiles `core`, `search`, `full`, and `raw`, SHALL state that CLI default export is `full` and web artifacts use `search`, and SHALL not overclaim native get for Ashby, Workable, Teamtailor, or Consider before exact-get evidence. Indeed, Glassdoor, LinkedIn, and Wellfound SHALL be documented as unsupported.

#### Scenario: Docs name profile defaults

- **WHEN** public docs describe `jobs export` or docs search artifacts after profile modules exist
- **THEN** they state that CLI default profile is `full`
- **AND** they state that web search artifacts use `search`

#### Scenario: Docs do not overclaim ATS get hooks

- **WHEN** public docs list built-in ATS capabilities
- **THEN** Ashby, Workable, and Teamtailor are not described as native get
- **AND** Consider exact-get is described only after it is proven

### Requirement: Source-policy 1780 grants stay blocked

Public docs and contributor instructions SHALL keep source-policy 1780 blocked pending written grants. This change SHALL NOT fabricate grants, broaden packaged source eligibility, or treat coverage expansion as legal permission to ingest blocked hosts.

#### Scenario: A contributor looks for 1780 unblocking

- **WHEN** a contributor reads source-policy or coverage docs during this change
- **THEN** source-policy 1780 remains blocked pending written grants
- **AND** overlay or household growth does not claim that grant

### Requirement: Web search artifacts stay on the search profile without live publish

Docs Jobs/Explorer SHALL continue to consume generated search artifacts rather than a live OpenOpps database. Those artifacts SHALL use the `search` profile field intent. Refreshing public data SHALL remain a maintainer regeneration path from local snapshots and SHALL NOT be performed as live publication from this change.

#### Scenario: Jobs workbench stays static

- **WHEN** a user opens the docs app jobs workbench
- **THEN** job rows load from generated search artifacts
- **AND** this change does not couple deploy to a live ATS sync or Workers upload

#### Scenario: Search artifacts do not carry raw payloads

- **WHEN** v7 or v6 search artifacts are generated after profiles exist
- **THEN** they follow `search` field intent
- **AND** raw payload snapshots remain in SQLite/Kaggle only
