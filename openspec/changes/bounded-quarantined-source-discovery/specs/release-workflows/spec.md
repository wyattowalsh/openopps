## ADDED Requirements

### Requirement: Discovery contracts have deterministic local and CI gates

OpenOpps SHALL provide thin Justfile recipes and mirrored CI validation for discovery schemas, sanitized fixtures, canonical bundle verification, replay determinism, promotion preview, selector closure, and accounting.

#### Scenario: A contributor validates discovery fixtures

- **WHEN** the contributor runs `just source-discovery-fixtures-check`
- **THEN** OpenOpps validates every tracked fixture and adversarial case without live network access
- **AND** repeated replay produces byte-identical canonical output

#### Scenario: A maintainer validates a quarantine bundle

- **WHEN** the maintainer runs `just source-discovery-manifest-check manifest=<path>`
- **THEN** the recipe invokes the documented offline verifier
- **AND** failures reproduce the corresponding CI validation behavior

### Requirement: Promotion preview is digest-bound and dry-run-first

OpenOpps SHALL provide a maintainer promotion workflow that consumes one exact quarantine manifest and defaults to a non-mutating repository diff preview.

#### Scenario: A maintainer previews promotion

- **WHEN** the maintainer runs `just source-discovery-promotion-preview manifest=<path>`
- **THEN** the workflow verifies the bundle and its root digest before candidate selection
- **AND** shows the proposed catalog, policy-gate, fingerprint, generated-data, test, and documentation effects
- **AND** does not edit, stage, commit, push, publish, or deploy

#### Scenario: Manifest identity changes after review

- **WHEN** manifest bytes, evidence members, selection, or root digest differs from the reviewed input
- **THEN** promotion refuses to apply
- **AND** a new preview and review are required

#### Scenario: Explicit local apply succeeds

- **WHEN** a maintainer separately requests apply for the exact reviewed bundle and selection
- **THEN** apply requires a separate maintainer-authored canonical decision bound to the exact reviewed digests
- **AND** requires a separately committed append-only ledger reservation with no current or historical application or revocation
- **AND** under one repository-scoped promotion lock, stages and double-generates the complete handed-off after-tree and verifies a candidate wheel before repository mutation
- **AND** exact-verifies all before/after bytes under an fsynced `prepared`/`applying`/`finalizing` recovery journal before installing owned paths
- **AND** only the promotion workflow's owned repository paths change
- **AND** deterministic catalog, handed-off generated-data, wheel-resource, private selector-envelope, and read-only v7 policy-input gates must pass
- **AND** catalog, all handed-off generated bytes, private envelope, receipt, and the applied ledger event must enter history in one reviewed commit or deterministic recovery restores all preimages and revokes the decision
- **AND** Git staging, commit, push, publication, and deployment remain separate authority boundaries

### Requirement: Public CI remains offline and live scouting remains private

OpenOpps SHALL use public repository CI only for offline replay of committed sanitized redistribution-safe fixtures. Unsanitized or live quarantine evidence SHALL remain in maintainer-controlled private storage, and this change SHALL NOT provision or activate a live schedule.

#### Scenario: Public discovery validation runs

- **WHEN** GitHub Actions validates discovery behavior
- **THEN** it checks out an immutable revision without persisted credentials and runs offline with network access disabled for discovery tests
- **AND** it consumes only committed sanitized redistribution-safe fixtures
- **AND** it does not upload unsanitized or live quarantine bundles, run a live scout, commit, push, open a pull request, publish datasets, or deploy services
- **AND** governance tests reject any live-scout `schedule:` trigger in the public repository

#### Scenario: A private live schedule is considered

- **WHEN** maintainers need recurring live scouting
- **THEN** this change supplies only a scheduler-agnostic least-privilege runbook/template for a maintainer-controlled private host and private output root
- **AND** provisioning, credential selection, schedule activation, retention, and live execution require separate explicit authority
- **AND** unavailable access reports a bounded blocked state without browser automation, scraping bypass, public artifact upload, or paid-service substitution

### Requirement: Discovery workflow documentation remains synchronized

OpenOpps SHALL keep README, CLI, configuration, operations, contributor documentation, portable skill documentation, Justfile recipes, CI jobs, OpenSpec tasks, and nested `AGENTS.md` files aligned with discovery and promotion behavior.

#### Scenario: A discovery contract or command changes

- **WHEN** a schema, budget, command, recipe, workflow, output field, skill definition, promotion gate, or scheduled-snapshot selector changes
- **THEN** corresponding documentation, semantic help tests, skill evals, CI governance tests, and nested instructions change in the same logical update
- **AND** docs distinguish quarantine evidence, approved catalog state, scheduled ingestion, and live publication proof

### Requirement: Active v7 ownership gates shared repository writes

OpenOpps SHALL treat the active `production-hardening-static-data-v7` change as the exclusive owner of ingestion/providers, cache/storage/migrations, v7 source-policy formats and inputs, the public `SourceSelector`, Kaggle/notebook surfaces, shared generated data, `Justfile`, and public workflows until an explicit path-level handoff is recorded.

#### Scenario: Discovery work reaches an overlapping path

- **WHEN** v7 remains active and no exact path-level handoff exists
- **THEN** discovery code may read and hash that path but does not modify it
- **AND** promotion apply and shared delivery tasks stop at `XV7`

#### Scenario: A shared path is handed off

- **WHEN** v7 archives or its owner records the exact handed-off paths and all prior writers have stopped
- **THEN** discovery records handoff-time digests before opening its one serialized shared writer
- **AND** non-handed-off ingestion, provider, cache, storage, migration, v7, public-selector, source-policy, Kaggle, and publication paths remain byte-identical

### Requirement: Release assurance separates evidence layers

OpenOpps SHALL report discovery rollout evidence separately for contracts, source, focused tests, generated repository state, build and package, clean CI, captured live scout, daily runtime, and publication.

#### Scenario: An implementation commit is pushed

- **WHEN** local gates permit an atomic conventional commit and push
- **THEN** maintainers verify the remote branch SHA and exact-SHA CI independently
- **AND** no live scout schedule, Kaggle mutation, Cloudflare mutation, or publication is inferred from source or CI success
