Use this page for local CLI operations and docs validation while working on OpenOpps v0.1. There is no hosted runtime to initialize; durable state lives in local SQLite files controlled by `OPENOPPS_` settings.

## Storage

SQLite is the default DB-backed storage mode:

```bash
uv run openopps admin db init
uv run openopps admin db status
uv run openopps sources sync a16z --metrics-json
uv run openopps jobs sync --provider any --metrics-json
```

The default database path is controlled by `OPENOPPS_DB_URL` and resolves to `openopps.db` for `sqlite:///openopps.db`.

`admin db init` runs Alembic migrations for the durable app SQLite schema. Existing unversioned OpenOpps ledgers are stamped after local schema repair hooks run. The optional HTTP response cache is separate and is not part of the Alembic migration history.

Use `status` or `doctor` to inspect the full local runtime state:

```bash
uv run openopps status
uv run openopps doctor --json
```

## Cache

The shared SQLite request cache stores successful JSON request payloads for source adapters and job providers. It records deterministic request identity, payload hash, selected headers, freshness timestamps, ETag/Last-Modified validators, and stale-on-error eligibility.

```bash
uv run openopps cache status
uv run openopps admin cache purge --namespace http-json --json
uv run openopps sources sync a16z --refresh-cache --metrics-json
uv run openopps jobs sync --provider any --refresh-cache --metrics-json
```

`--refresh-cache` bypasses cache reads for that operation and lets successful responses update cache state.

## Examples

Seed deterministic synthetic records for local demos and smoke tests without upstream network access:

```bash
uv run openopps examples seed --seed 42 --boards 4 --jobs-per-board 2 --json
uv run openopps jobs list --source example --json
```

## No-DB Source Sync

For one-off source extraction without persistence, use explicit JSONL output:

```bash
uv run openopps sources sync a16z --no-db --output /tmp/a16z-boards.jsonl
```

## Exports

```bash
uv run openopps boards export --format jsonl --output /tmp/openopps-boards.jsonl
uv run openopps boards export --provider ashbyhq --has-jobs --format jsonl --output /tmp/ashby-boards.jsonl
uv run openopps jobs export --remote Full --skill Python --format csv --output /tmp/openopps-jobs.csv
uv run openopps jobs export --source a16z --salary-min 150000 --format parquet --output /tmp/openopps-jobs.parquet
```

Use `jsonl` for auditability, `csv` for spreadsheet inspection, and `parquet` for analytics workflows. JSONL exports stream records as they are encoded. Empty JSONL and CSV exports produce empty files; empty Parquet exports produce a readable empty Parquet table. CSV exports neutralize spreadsheet formula-leading strings by prefixing a single quote; JSONL and Parquet preserve values as-is for machine processing.

`boards export` accepts the same board filters as `boards list`, including `--source`, `--provider`, `--market`, `--location`, `--domain`, `--has-jobs`, `--min-staff`, `--max-staff`, and `--limit`.

`jobs export` accepts the same job filters as `jobs list`, including `--source`, `--board`, `--provider`, `--location`, `--department`, `--team`, `--workplace-type`, `--remote`, `--employment-type`/`--type`, `--salary-min`, `--salary-max`, `--skill`, `--query`, `--posted-after`, `--posted-before`, and `--limit`. These filters use normalized job fields; raw upstream payloads remain exported for auditability but are not part of primary filtering semantics.

## Route Probing

The CLI route-probing command is dry-run-first:

```bash
uv run openopps admin providers probe-routes --source a16z --provider all --limit 25 --json
```

Use `--apply` only after inspecting matched routes.

## Validation

Run Python tests from the repository root:

```bash
uv run pytest
```

Run docs checks from the docs app:

```bash
cd docs
pnpm data:generate
pnpm types:check
pnpm build
rtk lint
```

`pnpm data:generate` refreshes package-derived provider/source metadata. `pnpm types:check` also regenerates that metadata before generating Fumadocs MDX artifacts, generating Next.js route types, and running TypeScript without emitting files.

## Troubleshooting

| Symptom                                | Check                                                                                                     |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| A source sync returns zero boards      | Run `uv run openopps admin sources test <source> --page-size 5` and check provider health.                |
| A board has provider hints but no jobs | Run `admin providers probe-routes` and inspect unknown route candidates.                                  |
| Cached data looks stale                | Rerun the operation with `--refresh-cache` or purge the relevant cache namespace.                         |
| Workday sync is slow                   | Lower `OPENOPPS_WORKDAY_CONCURRENCY` and narrow sync with `--source`, `--board`, or `--provider workday`. |
| Export output is unexpectedly empty    | Confirm the database has data with `uv run openopps admin db status` and inspect filters.                 |
| Docs navigation is stale               | Update `docs/content/docs/meta.json`, then run `cd docs && pnpm types:check`.                             |
